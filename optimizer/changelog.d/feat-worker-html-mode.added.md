Added: the worker setting `html_mode` (`--html-mode`, `html_mode` in `pagespeed.json` and `PATCH /v1/config`) chooses what the worker does with HTML: `off`, `markdown-static`, `markdown-rendered` or `full` (the default, today's behaviour). It replaces `disable_html`, which is still accepted everywhere (`true` is `off`, `false` is `full`) and still reported and written, so existing configurations and older readers of `pagespeed-shared.conf` keep working; when both are given, `html_mode` wins. The `markdown-*` modes write no optimized HTML for any page and keep only the Markdown copy for agents; HTML variants stored earlier under `full` are served until the page changes or is refreshed, so purge after switching to drop them at once. A configuration saved by an older console carries only `disable_html`, so restoring it sets `off` or `full`: a saved workbench configuration with `disable_html: false` moves a `markdown-*` worker to `full`, so set `html_mode` again after restoring one. On pages the nginx front stores, both `markdown-*` modes currently build the agent copy the same way. With a web-server module that stores HTML pages itself, the worker derives their Markdown copy only in a `markdown-*` mode with `agent_optimize` on; when upgrading, restart the optimizer before reloading the web server, because an older worker refuses the module's new notifications.
