Prioritize Critical CSS

This filter first instruments the page to discover which CSS selectors match anything in it. It uses the results to select the critical CSS rules and inlines those in <style> tags where the stylesheet <link> tags were. Each full stylesheet is preloaded from that same place and takes effect there as soon as it has arrived, without holding up the first paint.

When you load this page, you may see one of several things:

  • An unoptimized, uninstrumented page if pagespeed is still loading and processing the CSS resources on the page.
  • An unoptimized page with instrumentation code at the bottom, once pagespeed has obtained all the CSS resources the page contains.
  • A page with the critical CSS in <style> tags. Each of them is followed by a preload <link> for the full stylesheet and by a copy of the original <link> in a <noscript> block; a small script turns the preload into the stylesheet when the file has arrived. This page might also contain additional instrumentation code to ensure that the critical CSS is still valid.

The inlined rules cover everything in the page as browsers last reported it, so the page should look the same before and after the full stylesheet arrives. There are limits:

  • After the page's stylesheets change, pagespeed serves the page unoptimized for a few views, until browsers have reported on the new rules.
  • After the page's markup changes without its stylesheets changing, rules that newly apply can be late until a visitor's browser reports on the new markup; pagespeed asks for a report again after about a minute by default, and the wait is longer when the visitor who is asked does not report.
  • Content that a script adds while the page is loading takes its rules from the full stylesheet.
  • The browser reports which rules the page uses once it has loaded. Content that a script removes, hides or gives other class names before then can be painted without the rules that applied only to its earlier state, until the full stylesheet arrives.
  • For pages whose markup differs from visitor to visitor under one URL, leave this filter off.
