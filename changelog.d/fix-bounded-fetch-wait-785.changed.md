- **A negative rewrite deadline no longer makes a resource request wait for ever.** With `RewriteDeadlinePerFlushMs` or `InPlaceRewriteDeadlineMs` below zero, a request for a rewritten resource that had to be rebuilt waited, without limit, for its turn in the background optimization queue, and could hold up a page behind image optimization for other pages. It now waits up to the new `NegativeDeadlineFetchWaitMs` option (1000 ms by default, never more than `FetcherTimeOutMs`; server or virtual-host configuration only), then serves the original resource, cacheable only privately and for at most 5 minutes, while the optimization finishes in the background. The same applies to the stylesheets inside a combined stylesheet request. A combined script request cannot serve the originals, so it waits up to `FetcherTimeOutMs` (5 seconds by default) and then answers 503 with `Retry-After` and `Cache-Control: no-store`, on Apache, nginx, IIS and Envoy alike; the optimization still finishes, so a retry is served. Rewriting of HTML pages is unchanged.
