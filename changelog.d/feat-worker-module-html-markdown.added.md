Added: the worker derives the Markdown copy of an HTML page that mod_pagespeed's HTML store wrote, from the stored bytes alone: no browser runs and no request leaves the worker. It does so only in a `markdown-*` `html_mode` (`markdown-rendered` derives these pages the same way) with `agent_optimize` on, and only for a page the module stored for a host it vouched for; a stored entry that is not an HTML page, was not written by the module's HTML store or carries `Cache-Control: no-transform` is refused and counted in `notifications.rejected_module_render`. A permanent refusal (a page over `max_html_size`, compressed bytes, bytes that do not match the stored content hash, a failed extraction, or a copy below the fidelity floor) is recorded once for that content, so the module stops asking for the copy until the page changes or is stored again; after raising `max_html_size`, a page refused for its size is derived on its next store. The copy carries its own content hash, so the module can answer Markdown requests with an entity tag and a 304. The fidelity floor also applies to copies rendered for the nginx front: a page whose Markdown body holds fewer than 200 non-whitespace bytes gets no copy, and agents get the page itself (`agent_markdown.below_floor`); the same content is not rendered again for ten minutes. New counters: `agent_markdown.module_derived`, `module_withheld` and `module_withheld_skips`.
