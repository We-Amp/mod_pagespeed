Added: the worker setting `html_mode` (`--html-mode`, `html_mode` in `pagespeed.json` and `PATCH /v1/config`) chooses what the worker does with HTML: `off`, `markdown-static`, `markdown-rendered` or `full` (the default, today's behaviour). It replaces `disable_html`, which is still accepted everywhere (`true` is `off`, `false` is `full`) and still reported and written, so existing configurations and older readers of `pagespeed-shared.conf` keep working; when both are given, `html_mode` wins. The `markdown-*` modes write no optimized HTML for any page and keep only the Markdown copy for agents; HTML variants stored earlier under `full` are served until the page changes or is refreshed, so purge after switching to drop them at once. A configuration saved by an older console carries only `disable_html`, so restoring it sets `off` or `full`. On pages the nginx front stores, both `markdown-*` modes currently build the agent copy the same way.
