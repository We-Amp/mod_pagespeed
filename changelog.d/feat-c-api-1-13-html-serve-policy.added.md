Added: C API 1.14, the HTML serve policy for front ends that store HTML pages themselves and serve their Markdown copy. `ps_html_serve_classify` decides from the request and the stored facts whether the stored page or its Markdown copy may answer; Markdown is chosen only by the request's own preference, never for a request with Range, If-Range or Origin, a method other than GET or HEAD, a parent stored with `no-transform` or a request carrying it, a copy the deriver withheld, or an entry dated in the future, and a 304 is answered only for a copy the same call would serve. `ps_html_store_write_params` computes the insert time in one place and refuses an inbound `Age` it cannot trust; `ps_html_stored_facts_from_reads`, `ps_html_markdown_etag`, `ps_if_none_match_matches_weak`, `ps_html_serve_reason_name` and `ps_read_shared_config_html_mode` complete the set. `ps_html_store_classify` accepts the serve modes, `PS_NOTIFY_FLAG_HTML_STORED` lets a module name a page it stored for a host it vouched for, and the decision line gains `vhost_added` and serve-side lines. Additive: callers built against 1.12 are unaffected. Restart the optimizer before reloading a web server whose module sends the new flag.
