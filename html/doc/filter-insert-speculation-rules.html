Insert Speculation Rules

Objective

Speed up same-origin navigations by letting the browser prefetch links before the user clicks them.

Configuration

The 'Insert Speculation Rules' filter is enabled by specifying:

Apache:
ModPagespeedEnableFilters insert_speculation_rules
Nginx:
pagespeed EnableFilters insert_speculation_rules;

in the configuration file. The filter is not part of any rewrite level, so it is always opt-in.

Description

The Speculation Rules API lets a page declare which links the browser may fetch speculatively, ahead of the user's click. This filter injects a conservative ruleset that prefetches same-origin documents with moderate eagerness, which means the browser typically starts the prefetch when the user hovers over or starts interacting with a link. When the user then navigates, the destination document is already in the browser's cache, making the navigation feel near-instant.

Operation

This filter inserts a single script tag at the end of the body: 

<script type="speculationrules">
{"prefetch":[{"where":{"href_matches":"/*"},"eagerness":"moderate"}]}
</script>

The href_matches pattern is resolved against the document's own origin, so only same-origin links are ever prefetched. The filter backs off and injects nothing when:

  • the document is an AMP document, where <script type="speculationrules"> is not valid;
  • the document already contains a <script type="speculationrules"> ruleset of its own;
  • the response status is not 200, or the response sets cookies, or is marked Cache-Control: no-store;
  • the page's Content-Security-Policy does not permit inline scripts;
  • the request negotiates an AI-agent variant (Accept: text/markdown), keeping agent-facing payloads free of browser-only hints.

Example

The example below shows the HTML before rewriting: 

<html>
  <head>
  </head>
  <body>
    <a href="/products.html">Products</a>
    <a href="/contact.html">Contact</a>
  </body>
</html>

and after rewriting: 

<html>
  <head>
  </head>
  <body>
    <a href="/products.html">Products</a>
    <a href="/contact.html">Contact</a>
    <script type="speculationrules">{"prefetch":[{"where":{"href_matches":"/*"},"eagerness":"moderate"}]}</script>
  </body>
</html>

Limitations

The Speculation Rules API is currently implemented in Chromium-based browsers (Chrome, Edge, Opera). Other browsers ignore the script tag entirely, so the only cost there is a few extra bytes of HTML.

This version of the filter does not support exclusion patterns. If your site has same-origin links whose fetch has side effects (for example logout links implemented as GET requests), either fix those endpoints to require POST, or add your own speculation-rules script to the page — the filter never injects a second ruleset next to an existing one. A configurable exclusion list may be added as an option in a future release.

Risks

This filter is considered low risk for typical content sites. Prefetching adds some extra load on the server for links the user may never click; the moderate eagerness setting keeps this modest.

If a downstream cache serves the HTML to all clients regardless of browser, the injected tag is still harmless for non-supporting browsers. The filter suppresses injection for AI-agent requests that negotiate Accept: text/markdown, matching the Vary: Accept key used by the agent-optimize negotiation, so cached agent-facing variants stay clean.
